# HDR 후처리 — 프로토타입 03

이 문서는 구현 내용과 사용자가 직접 화면을 조정하는 방법이다. 사용자 작업 원칙에 따라 빌드·테스트·실행·화면 확인은 수행하지 않았다. 아래 기본값은 시각적으로 검증된 최종 값이 아니라 조정 가능한 출발값이다.

## 렌더링 순서

1. 월드를 부동소수점 HDR 텍스처에 그린다.
2. 밝은 픽셀을 추출하고 축소·가우시안 블러를 적용해 블룸 이미지를 만든다.
3. 월드 전체를 별도로 흐리게 만든다.
4. 중심에서 바깥으로 갈수록 원래 월드와 흐린 월드의 혼합 비율을 높인다.
5. 블룸을 합성하고 부드러운 비네트를 적용한다.
6. 노출과 톤 매핑으로 HDR 밝기를 화면에 표시할 범위로 변환한다.
7. 한글 HUD·대사·지도·상호작용 안내를 마지막에 선명하게 그린다.

기존의 가장자리 암막 사각형은 제거했다. 현재 비네트와 가장자리 블러는 화면에 이미 그려진 장면 텍스처를 입력으로 사용하는 후처리다. 건물·바닥을 다시 생성하거나 카메라 위치를 바꿔 만드는 효과가 아니다.

## HDR과 네온

월드 색상 버퍼는 GL_RGBA16F를 사용한다. 기존에 코드에서 지정한 색은 sRGB로 취급하고 월드를 그릴 때 선형 값으로 변환한다. 네온 간판·테두리·창문과 일부 캐릭터·드론의 발광 요소에는 별도의 발광 강도를 부여한다.

선형 색에 적용하는 밝기 배율은 다음과 같다.

~~~text
1 + 오브젝트의 emission × 설정의 emission_gain
~~~

밝기가 1.0을 넘어도 월드 버퍼에서 잘리지 않으므로 블룸 추출에 사용할 수 있다. 최종 단계에서 지수형 톤 매핑과 sRGB 인코딩을 한 번 적용한다. UI는 이미 후처리된 화면 위에 기존 색으로 그린다.

이 구현은 내부 HDR 렌더링을 일반 SDR 창으로 표시하는 방식이다. HDR 모니터나 Windows HDR 활성화가 필요하지 않으며 HDR10 출력 기능을 추가한 것은 아니다. 실제 광원·물리 반사를 구현한 것도 아니므로 기존 도로 반사와 빛 번짐 도형은 연출 요소로 남아 있다.

## 직접 비교하는 조작

| 입력 | 동작 |
|---|---|
| F5 | 전체 후처리 켜기·끄기. 끄면 기본 화면으로 직접 렌더링 |
| F6 | 블룸 켜기·끄기 |
| F7 | 비네트 켜기·끄기 |
| F8 | 가장자리 블러 켜기·끄기 |
| [ / ] | 노출을 0.1씩 감소·증가 |
| F9 | 후처리 설정 파일 다시 읽기 |
| Tab | HUD를 숨겨 월드 화면만 보기 |

왼쪽 후처리 패널에 효과별 설정과 현재 노출이 표시된다. 전체 후처리가 꺼져 있으면 개별 효과가 켜짐으로 설정되어 있어도 적용되지 않는다. 개별 설정은 전체 효과를 다시 켰을 때 사용한다.

F2는 기존처럼 게임 위치와 NPC 상태를 초기화하며 후처리 설정은 바꾸지 않는다. 키로 바꾼 값은 메모리에만 유지되고 파일에 자동 저장하지 않는다.

## 설정 파일과 다시 읽기

원본은 SimpleGame/Data/Rendering/postprocess.cfg다. 빌드 후 작업으로 EXE 옆 Data/Rendering/postprocess.cfg에 복사된다. 자원 경로 규칙에 따라 실행 파일 옆의 파일을 먼저 읽는다.

**실행 중 F9로 즉시 반영하려면 EXE 옆의 설정 파일을 수정한다.** 소스 폴더의 원본만 수정한 경우에는 사용자가 다시 빌드해 복사하거나 출력 폴더의 파일도 갱신해야 한다. 최종적으로 유지할 값은 소스의 설정 파일에도 반영한다.

설정은 UTF-8, key=value 형식이다. # 뒤는 주석이며 소수점은 점을 사용한다. 다시 읽기는 파일 전체가 유효할 때만 적용한다. 알 수 없는 키, 중복 키, 잘못된 숫자와 범위, 잘못된 시작·끝 반경이 있으면 이전 설정을 유지하고 콘솔에 오류를 표시한다. 파일에서 생략한 항목은 기본값으로 돌아간다.

| 키 | 기본값 | 허용 범위·의미 |
|---|---:|---|
| enabled | 1 | 0 또는 1, 전체 후처리 |
| bloom | 1 | 0 또는 1, 밝은 부분의 빛 번짐 |
| vignette | 1 | 0 또는 1, 가장자리 어둡게 |
| edge_blur | 1 | 0 또는 1, 가장자리 흐리게 |
| exposure | 1.15 | 0.25~4, 톤 매핑 전 노출 배율 |
| emission_gain | 1.0 | 0~8, 월드 발광 요소의 강도 배율 |
| bloom_strength | 0.28 | 0~2, 블룸 합성 강도 |
| bloom_threshold | 1.0 | 0~8, 선형 밝기에서 블룸을 추출하는 기준 |
| bloom_knee | 0.5 | 0~1, 추출 기준 주변의 부드러운 전환 |
| bloom_radius | 1.8 | 0.1~6, 블룸 블러 샘플 간격 |
| bloom_iterations | 3 | 정수 1~6, 가로·세로 블러 반복 횟수 |
| vignette_strength | 0.38 | 0~0.95, 바깥쪽 최대 암화 강도 |
| vignette_start | 0.32 | 0~1.4, 암화가 시작되는 반경 |
| vignette_end | 1.4 | 0.1~2, 암화가 최대에 도달하는 반경 |
| edge_strength | 0.65 | 0~1, 흐린 이미지의 최대 혼합 비율 |
| edge_start | 0.55 | 0~1.4, 흐림이 시작되는 반경 |
| edge_end | 1.3 | 0.1~2, 흐림이 최대에 도달하는 반경 |
| edge_radius | 2.6 | 0.1~6, 가장자리용 블러 샘플 간격 |

반경은 화면의 가로·세로 반폭을 각각 1로 정규화한 타원 기준이다. 중심은 0, 각 변의 중앙은 1, 모서리는 약 1.414다. 각 end는 해당 start보다 0.01 넘게 커야 한다.

중심까지 흐려지면 edge_start를 높이고, 가장자리가 너무 흐리면 edge_strength 또는 edge_radius를 낮춘다. 네온이 지나치게 퍼지면 bloom_strength를 먼저 낮춘다. 주변 건물까지 번지면 bloom_threshold를 높여 밝은 요소만 추출한다. 비네트가 답답하면 vignette_strength를 줄이거나 vignette_start를 높인다.

## 버퍼·성능·예외 처리

- 월드 버퍼 한 개와 블룸·가장자리 블러용 버퍼 각 두 개를 사용한다.
- 월드 버퍼는 실제 표시 영역 크기를 따르고, 블러 버퍼는 가로·세로 절반 크기다.
- 가로·세로 분리 가우시안 블러를 사용한다. 블룸은 설정 횟수, 가장자리 블러는 두 번 반복한다.
- 꺼진 효과의 추출·블러 패스는 생략한다.
- 창 크기가 바뀌면 필요한 버퍼를 새로 만들고 이전 버퍼를 해제한다. 새 버퍼 생성 실패 시 기존 버퍼를 유지한다.
- 큰 창은 하드웨어 텍스처 한도와 한 축 4096픽셀 한도 안에서 내부 해상도를 유지한다.
- 초기 셰이더·HDR 버퍼 준비 실패 시 콘솔에 오류를 알리고 기본 렌더링으로 진행한다. HUD에도 후처리 사용 불가 상태를 표시한다.
- 버퍼들은 영구적인 프레임 기록이 아니며 매 프레임 덮어쓴다. 여러 프레임의 잔상을 쌓는 모션 블러는 없다.

가장자리 블러는 화면 위치를 기준으로 한 연출이다. 깊이 버퍼를 사용하는 피사계 심도와는 다르며 건물 뒤편의 실제 초점 거리를 계산하지 않는다.

## 사용자가 확인할 항목

1. 새 셰이더 네 개와 설정 파일이 출력 폴더에 복사되어 있는 상태에서 직접 빌드·실행한다.
2. F5로 전체 후처리 전후를 비교하고, F6으로 네온의 빛 번짐 변화를 본다.
3. F7·F8을 각각 꺼 어두워지는 효과와 흐려지는 효과를 구분한다.
4. 중앙 플레이어는 선명하고 화면 가장자리는 부드럽게 변하는지 본다.
5. 한글 대사·지도·HUD가 번지거나 어두워지지 않는지 본다.
6. 창 크기 변경과 줌, Tab으로 HUD 숨김을 사용해 화면이 뒤집히거나 이전 프레임이 남지 않는지 본다.
7. EXE 옆 설정을 수정하고 F9로 반영하며 잘못된 값은 이전 설정을 유지하는지 본다.

현재 문서에는 FPS나 시각 품질의 측정·검증 결과를 포함하지 않는다.
