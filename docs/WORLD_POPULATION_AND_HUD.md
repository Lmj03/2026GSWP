# 월드 인구와 HUD 정리

2026-10-13 사용자 요구 6개를 반영한 변경 기록이다. **마을·NPC의 최신 생성 규칙은 2026-10-20 [SEVEN_TOWNS.md](SEVEN_TOWNS.md)가 우선한다.** 아래의 청크당 NPC 생성 방식은 마을 명부 방식으로 교체했다. 게임 빌드·실행·시각 결과 확인은 사용자가 진행한다.

## 건물과 가독성

- 잔광 지구의 건물 이름·중심 위치·도로·스토리 위치는 유지한다. 바닥 외곽을 사방 0.35타일씩 줄여 기존 가까운 건물 사이의 0.45타일 간격을 1.15타일로 넓혔다. 표시와 충돌에 같은 수정 데이터를 사용한다.
- 외곽 생성 건물 사이 최소 간격은 1.25 → **2.0타일**이다. 청크 경계에서 1.1타일을 비워 생성 청크끼리 붙었을 때도 여유 공간이 남는다.
- 일반 구역은 청크당 최대 1~2개, 광장은 최대 1개다. 후보를 36회 조사해 도로를 침범하지 않는 필지를 찾는다. 안전한 필지가 없으면 강제로 배치하지 않는다.
- 생성 건물의 크기와 높이를 낮춰 길과 캐릭터를 덜 가리도록 했다. 월드 좌표 기반의 지역 분류와 건물 재현성은 유지한다.
- 건물 바닥과 플레이어 사이 거리가 2.5타일 이내일 때만 이름과 아르카디아 표어를 표시한다. 멀리서는 네온 장식만 남는다. HUD 숨김 상태에서는 이름도 숨긴다.

## NPC와 일반 몹의 생성

`Data/level1.level`은 버전 2로 변경했다. 기존 `enemy alley_thug`, `toll_thug`, `depot_thug` 좌표 세 줄과 반드시 적 3명을 읽어야 하는 조건을 제거했다. 보급 상자·은신처·스토리 인물은 유지한다.

NPC는 일반 청크에서 0~3명, 시장에서 1~4명을 후보로 생성한다. 구역에 맞는 상인·생산직 우선 배치와 기존 직업별 행동·개인 기억·악명 규칙을 유지한다. 기존 이름 있는 주민과 스토리 인물도 유지한다. 후보는 도로·보행 공간을 사용하며 건물·스토리 지점·다른 개체와 겹치지 않는 위치를 찾는다. 실제 수는 안전한 위치의 확보 여부에 따라 적을 수 있다.

일반 몹은 광장 0명, 산업 구역 0~2명, 나머지 구역 0~1명의 슬롯을 청크별로 정한다. 새 게임/F2 초기화마다 인구 시드가 달라지고 같은 플레이의 재방문에서는 슬롯 ID와 후보를 유지한다. 건물은 인구 시드와 무관하다.

게임 진행 중 2초마다 아직 생성하지 않은 주변 슬롯을 검토한다. 한 번에 최대 6개, 전체 EnemyActor는 스토리 인물을 포함해 최대 48개다. 플레이어 주변 28타일 이내에서만 생성한다. 플레이어와 은신처 주변 4.5타일, 스토리 지점 주변 1.8타일, 다른 개체·건물과 겹치는 위치는 피한다. 초기 월드 준비 이후 새로 나타나는 살아 있는 몹은 화면 바깥에서 생성한다.

전리품 회수 후 약 25초가 지나면 기존 자리로 되살리는 대신 해당 청크의 다른 안전한 지점을 찾는다. 화면 안이나 플레이어 가까이에 안전한 지점이 없으면 2초 뒤 다시 조사한다. 몹의 귀환·추적·공격 예고·주먹/칼 판정과 자동 습득 규칙은 유지한다. 스토리 가해자는 이 반복 생성에 참여하지 않는다.

## 스트리밍과 진행도

생성 몹은 `streamed` 아래 EnemyActor로 등록하며 전리품·공격 예고 Actor를 자식으로 둔다. 위치·귀환점·공격 예고는 현재 장면 좌표다. 스토리 가해자는 `authored` 좌표를 사용한다. `EnemyLocal`을 전투·전리품·지도·목표에 공통 적용했고 모니터링 JSON도 두 좌표계를 구분한다.

범위를 벗어난 몹은 ActorView에서 제외한 뒤 SceneGraph를 통해 자식과 함께 제거한다. 손상·처치·전리품·재생성 이력이 있는 슬롯은 청크 내부 좌표로 기억하며 재방문 시 복원한다. 전리품은 이동만으로 사라지거나 새 보상으로 복제되지 않는다. 기억 데이터는 디스크 저장이 아니며 게임 종료/F2에서 초기화한다. 의미 있는 NPC/몹 기록은 방문한 구역 수에 따라 늘어날 수 있다. 로드 해제 상태의 몹 타이머는 멈춘다.

훈련의 `제압 3회 / 전리품 회수 3회`는 활성 적 목록에서 계산하지 않고 누적 카운터로 관리한다. 같은 슬롯의 반복 재생성은 훈련 진행도를 중복 증가시키지 않는다. 구역 이동·사망 복귀 이후에도 진행도가 유지되며 조건 충족 후 은신처에서 한 번 보고하면 보상을 받는다. 이후 일반 몹 파밍은 계속 가능하다.

신규 몹 등록은 SceneGraph 갱신 이후 실행해 삭제 예약 ID와 충돌하지 않도록 했다. `population spawn_mobs`, `unload_mobs`, `respawn`, `generation` 이벤트를 기존 프로파일 로그에 기록한다. 로컬 JSON의 몹 목록은 생성 몹을 포함하며 `streamed`, `generation` 필드를 추가했다.

## 플레이 UI

위·아래 전체 화면 HUD 띠, 게임 제목/감시 문구, 키 목록, 후처리 설정 패널, 청크 좌표, 중복 목표 화살표를 제거했다. NPC의 직업·행동·악명 상태를 모든 개체 위에 표시하던 방식도 정리했다. 주변 NPC 이름과 가까운 위협의 체력·공격 예고만 제공한다. 상세 NPC/성능 수치는 로컬 모니터에서 확인한다.

남기는 정보는 현재 목표, 주변 지도, 지역명·인지도, 레벨·장착 장비, 체력·경험치, 크레딧·회복제, 일시적인 획득/성장/피해 알림이다. 정당성 수치는 기존 방침대로 HUD에서 직접 표시하지 않고 기록과 반응을 사용한다.

대화 선택지, 거점의 휴식/장비 교체/제작/창고 동작, 닫기, 기록 이전/다음, 지도, 회복제를 마우스로 선택할 수 있다. HUD의 목표 제목을 누르면 기록이 열리고 작은 지도를 누르면 지도가 확장된다. 키 안내는 화면에 표시하지 않지만 기존 키 조작은 계속 동작한다.

렌더러는 창 크기에 맞춰 논리 영역을 확장하고 전체 뷰포트를 사용한다. 셰이더도 논리 화면 크기를 uniform으로 받도록 변경해 종횡비 변화에서 늘어짐이나 레터박스가 생기지 않게 했다. 기본 창은 기존 1280×800이며 글자 배율 1.3을 유지한다.

## 확인 범위

한글 키, 프로젝트 등록, 장면 함수 정의, 문서/데이터 형식 및 코드 포맷을 소스 기준으로 확인한다. 게임·브라우저 실행, 빌드 및 성능 측정은 하지 않는다. 사용자 확인 시 청크 경계 왕복, 음수/먼 월드 좌표, 제압 후 전리품을 남긴 채 왕복, 사망 복귀, 훈련 보고, F2 초기화, 마우스 메뉴와 창 크기 변경을 확인하면 된다.
