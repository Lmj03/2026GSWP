# 로컬 월드 모니터링

게임이 현재 로드한 Actor 상태를 JSON으로 전송하고, 로컬 HTTP 수신 서버가 이를 받아 HTML 대시보드와 분석용 JSONL 로그에 반영한다. C++ · OpenGL 게임 구조를 유지하며 외부 패키지나 웹 서비스를 요구하지 않는다.

## 사용 방법

저장소 루트에서 PowerShell 터미널을 열어 실행한다.

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\start_monitor.ps1 -OpenBrowser
```

대시보드 주소는 **http://127.0.0.1:8765/** 이다. 터미널은 수신 서버 실행 동안 열어 두고, 종료하려면 `Ctrl+C`를 누른다. 런처는 PATH의 Python을 사용하며, 없으면 이 PC의 Codex에 포함된 Python을 찾는다. Python 3.9 이상이면 다음 명령으로 직접 시작할 수도 있다.

```powershell
python .\tools\monitor_server.py --open-browser
```

사용자가 새 코드로 게임을 빌드하고 실행하면 기본적으로 1초마다 데이터가 들어온다. 서버와 게임의 시작 순서는 상관없다. 서버가 나중에 켜지거나 다시 시작되어도 게임은 다음 메시지부터 재시도한다. HTML을 파일로 직접 여는 대신 위 주소로 접속해야 한다. HTML/JS/CSS는 모두 로컬에서 제공되고 인터넷 연결이 필요 없다.

게임이 포커스를 잃으면 기존 설계에 따라 시뮬레이션이 멈춘다. 모니터 전송은 계속되며 화면에 `일시정지 · 포커스 없음`이 표시된다. 대화·지도·거점 메뉴·기록·사건 연출 등 NPC/전투를 멈추는 상태도 표시한다. 사건 연출 및 플레이어 재생성 자체의 진행까지 정지한다는 의미는 아니다.

## 화면과 집계 기준

- 전체: 활동 중인 NPC 수, 전투 가능한 몹 수, 살아 있는 적대 NPC 수, 관측 마을/청크/Actor 수, FPS와 draw call 수.
- NPC: 이름/Actor ID, 마을, 직업, 행동, 체력, 악명, 신뢰, 범죄/기여 횟수, 적대/활성/스토리 여부, 청크 좌표. 상세 버튼은 도움·사과·전리품 회수 여부 등 모든 NPC 필드를 보여준다. 이름/ID 검색과 마을·직업·행동·상태 필터를 제공한다.
- 마을: NPC 및 몹 집계, 평균 악명·신뢰·체력 비율, 직업/행동 분포, 현재 위험 상태, 관측한 청크 수와 전체 청크 수.
- 몹: EnemyActor의 체력, 활성 여부, 연출 대기/공격 준비/공격 대기/제압 상태, 재생성 타이머, 전리품 여부.
- 부가 정보: 플레이어 레벨·체력·정당성·인지도·스토리 목표, 최근 완료 프레임의 CPU 시간/인스턴스/업로드량, JSON 전송 성공·실패·대기 메시지 교체 횟수, 최신 JSON 보기/저장.

`NPC 로드 수`는 전체 NPC 명부 중 `loaded`가 참인 Actor 전체, `활동 수`는 `active && enabled`, `생존 수`는 활동 중이며 체력이 0보다 큰 NPC다. 제압/사망 수는 활동 중이며 체력이 0인 NPC다. `적대 수`는 살아 있는 활동 NPC 중 `hostile`이 참인 수다. 악명이 높아 적대하는 시민은 NPC 집계에만 포함되고 몹에 중복 포함되지 않는다.

`몹 로드 수`는 현재 스트리밍 범위에 있는 EnemyActor 전체, `생존 수`는 활성 상태이며 체력이 0보다 큰 몹, `전투 가능 수`는 그중 AI 갱신이 활성화된 몹이다. 의료 기업 후손이 첫 사건 연출에 등장해도 전투가 활성화되기 전에는 전투 가능 수에 포함하지 않는다. 제압 수는 활성 상태이며 체력이 0인 몹이다. 일반 몹은 청크별로 생성·해제되며 외곽 구역에도 나타난다. 스토리 가해자는 기존 수제 배치 좌표를 유지한다. 관측 범위를 벗어난 개체는 목록에서 제외된다. `streamed`는 생성 몹 여부, `generation`은 해당 슬롯의 재생성 횟수다.

## 마을과 무한 월드

2026-10-20부터 `Data/World/towns.world`에 정의한 7개 실제 마을을 사용한다. 각 마을은 7×7청크이며 잔광 지구의 수제 핵심 구역도 잔광 지구 전체에 포함한다. 마을 사이 및 바깥은 `roads` 영역이며 여덟 번째 마을로 집계하지 않는다. 세부 배치·인구·도로 이동 기준은 [SEVEN_TOWNS.md](SEVEN_TOWNS.md)를 따른다.

전체 NPC 명부는 490개 ID를 포함한다. NPC 행에 `loaded`가 거짓이면 화면 밖의 명부이며, 같은 NPC의 도로 이동과 목적지·개인 이력을 유지한다. 로드되지 않은 NPC는 직업·전투 전체를 시뮬레이션하지 않는다. 현재 인구·치안·적대 인구는 각 마을 카드에 명부 기준으로 표시하고, 로드 NPC/몹과 직업·행동 평균은 현재 관측 범위로 구분한다. 이동 중인 NPC는 실제 위치에 따라 마을 또는 도로 영역으로 분류한다.

일부 청크만 로드한 마을도 전체 49청크와 관측 청크 수를 함께 표시한다. 7개 마을은 미로드 상태여도 카드에 남는다. 무한 월드 전체의 총인구나 아직 정의하지 않은 지역의 수치로 해석하면 안 된다. `remembered_npcs`는 변경 이력 개수이며 전체 명부 인구와 다르다.

마을 상태는 모니터의 요약 규칙이며 게임 AI를 변경하지 않는다.

| 상태 | 현재 관측값의 조건 |
| --- | --- |
| 위험 | 관측된 적대 NPC/전투 가능한 몹/갈취 행동 또는 전체 마을 명부의 활동 가능한 적대 인구가 존재 |
| 불안 | 위험 조건이 없고, 살아 있는 활동 NPC 중 악명 60 이상 존재 |
| 안정 | 위 조건이 없고 로드 NPC 또는 마을 명부에 활동 가능한 생존 NPC 존재 |
| 인구 미관측 | 위 조건에 해당하지 않으며 살아 있는 활동 NPC 없음 |

평균과 직업/행동 분포는 살아 있는 활동 NPC를 대상으로 계산한다. 대상이 없으면 평균은 `null`이며 화면에 `—`로 표시한다. 스토리상 비활성인 경호원의 악명 등이 구역 평균을 왜곡하지 않는다.

## 전송 구조와 설정

```text
메인 스레드: SceneGraph / 게임 상태 복사 + 최근 완료 프레임 통계
    → JSON 직렬화 (기본 1초 주기)
    → 최신 메시지 1개만 대기시키는 큐
별도 전송 스레드: WinHTTP POST → 127.0.0.1:8765/api/snapshot
Python 수신 서버: 검증 → 마을별 집계 → JSONL 기록
HTML: GET /api/snapshot을 약 1초마다 조회 → 화면 갱신
```

네트워크 호출은 메인/OpenGL 스레드에서 실행하지 않는다. JSON 복사와 직렬화 비용은 메인 스레드에 남는다. 느린 수신기로 인해 큐가 무한히 늘어나지 않으며 아직 전송하지 않은 오래된 스냅샷은 최신 스냅샷으로 교체한다. 각 네트워크 단계에는 500ms 제한을 설정한다. 게임 종료 시 대기 메시지를 버리고 전송 스레드를 정리하므로 진행 중 요청의 제한 시간만큼 잠시 기다릴 수 있다. 서버가 없을 때 콘솔에는 최초 실패와 연결 복구만 알리고 반복 실패로 매초 로그를 채우지 않는다.

`SimpleGame/Data/Monitoring/monitor.cfg`:

```text
enabled 1
interval_ms 1000
port 8765
```

- `enabled 0`이면 전송을 끈다.
- `interval_ms`: 250~60000. 게임을 다시 시작하면 읽는다.
- `port`: 1024~65535. 변경 시 서버도 `-Port 8766` 또는 `--port 8766`처럼 동일한 포트로 실행한다.
- 목적지 호스트는 `127.0.0.1`로 고정한다. 수신 서버 역시 해당 주소에만 바인딩한다.
- 설정 파일은 기존 데이터 복사 규칙에 따라 빌드 출력의 `Data/Monitoring/`에 복사된다. 배포된 출력 폴더의 설정이 우선한다.

WinHTTP의 동기 요청을 별도 스레드에서 사용한다. 모든 빌드 구성에 `winhttp.lib`를 추가했다. [WinHttpSendRequest 문서](https://learn.microsoft.com/en-us/windows/win32/api/winhttp/nf-winhttp-winhttpsendrequest) 및 [WinHttpReceiveResponse 문서](https://learn.microsoft.com/en-us/windows/win32/api/winhttp/nf-winhttp-winhttpreceiveresponse)에 따른 요청/응답 순서와 전송 버퍼 수명을 유지한다. 전송 스레드는 Actor, SceneGraph, OpenGL 및 FrameProfiler에 접근하지 않는다.

## JSON 규약

모든 메시지는 UTF-8 전체 스냅샷이다. `POST /api/snapshot`, `Content-Type: application/json; charset=utf-8`로 보낸다. 최대 본문 크기는 2MiB다. 정상 수신은 `204`, 잘못된 필드/형식은 `400`, 역순/중복 순번은 `409`, 초과 크기는 `413`, 다른 콘텐츠 형식은 `415`다. 스키마 버전 1 이외에는 거부한다.

완전한 예시는 `tools/monitor/sample.snapshot.json`이다. **예시 수치이며 실제 성능이나 인구를 나타내지 않는다.** 서버는 예시를 자동 로드하지 않는다.

| 필드 | 의미 |
| --- | --- |
| `schema_version`, `type`, `scope` | `1`, `world_snapshot`, `loaded_chunks` |
| `session_id` | 프로세스 ID + 시작 시각; 게임 재실행 시 변경 |
| `sequence` | 세션 내에서 증가하는 메시지 순번 |
| `reset_epoch` | F2 등 월드 초기화 횟수; 초기 로드도 포함 |
| `interval_ms`, `uptime_seconds` | 수집 주기 및 모니터 시작 이후 실제 경과 시간 |
| `world` | 원점 청크, 로드 청크 수, 전체 Actor 수, 기억된 NPC 이력 수 |
| `simulation` | 포커스, NPC/전투 일시정지 여부 및 원인 |
| `player` | 레벨, 체력, 정당성, 인지도, 스토리 단계(0~7), 목표, 마을, 위치 |
| `profiling` | 최근 완료 프레임 통계; FPS는 최근 1초 단위로 갱신 |
| `transport` | 이전 전송까지의 성공·실패·대기 교체 횟수 |
| `villages` | 마을 ID/이름, 관측 청크 수, 전체 청크 수 |
| `npcs` | 전체 NPC 명부의 상태·개인 이력·직업·로드 여부·이동 목적지 |
| `mobs` | 현재 로드 범위 내 EnemyActor 각각의 상태 |

`position`은 `chunk_x`, `chunk_y`와 청크 내부 좌표 `local_x`, `local_y`로 구성한다. **청크 좌표와 프레임 번호는 문자열**이다. 큰 int64 월드 좌표를 JavaScript의 숫자로 바꾸지 않아 정밀도를 보존한다. JSON 문자열의 따옴표·역슬래시·제어문자는 이스케이프하고 한글은 UTF-8로 유지한다.

`GET /api/snapshot` 응답은 `snapshot` 원본과 서버가 계산한 `summary`를 포함한다. 추가 필드 `connected`, `stale`, `age_seconds`, `received_at`, `recording_enabled`, `record_path`, `record_error`로 상태를 확인할 수 있다. 데이터가 없으면 `snapshot`과 `summary`는 `null`이다. 최신 수신 후 `max(5초, 수집 주기의 3배)`가 지나면 연결 지연으로 표시하고 마지막 데이터를 유지한다. 서버는 한 번에 **한 게임 프로세스**의 최신 상태를 표시한다. 여러 게임 프로세스를 동시에 실행하면 마지막 도착 세션으로 화면이 바뀐다.

`GET /api/health`는 서버 확인용이다. HTML은 요청을 중첩하지 않고 응답 후 다음 조회를 예약한다. JSON 문자열은 `textContent`로 표시하며 HTML로 실행하지 않는다. 수신기는 로컬 Host/Origin 및 JSON 형식을 확인하고 지정한 정적 파일만 제공한다.

## 분석 로그

기본 경로는 `tools/monitor/Logs/world-<UTC 시작시각>-<PID>-<분할번호>.jsonl`이다. 유효한 메시지마다 수신 시각, 원본 스냅샷, 집계 결과를 한 줄씩 기록한다. 16MiB를 넘기기 전에 다음 파일로 분할하며 오래된 파일을 자동 삭제하지 않는다. `Logs`는 Git 추적에서 제외된다. 필요하면 사용자가 보관/정리한다.

```powershell
# 기록 없이 확인
powershell -ExecutionPolicy Bypass -File .\tools\start_monitor.ps1 -NoRecord
# 별도 경로에 기록
python .\tools\monitor_server.py --record-dir D:\GameAnalysis\Logs
```

디스크 기록이 실패하면 기록을 중단하고 대시보드/콘솔에 원인을 표시한다. 최신 데이터 수신은 유지한다. 로그로 세션/리셋/악명/직업/인구/성능 변화를 비교할 수 있으며, 기존 `render-*.csv`의 프레임 번호와도 대조할 수 있다. 전송 실패·대기 교체로 빠진 메시지는 복원하지 않는다.

## 확인 범위 및 문제 해결

이번 구현에서는 게임 빌드, 게임 실행, 브라우저 결과 확인을 수행하지 않는다. Python 프로토콜/집계 검증, Python·JavaScript 구문 검사, 프로젝트 등록·문구·소스 포맷을 확인한다. 실제 연결, FPS 및 화면 확인은 사용자가 게임을 빌드한 뒤 진행한다.

```powershell
python .\tools\test_monitor_protocol.py
python .\tools\validate_story_content.py
```

- 연결 대기: 새 코드를 빌드했는지, 게임 설정 `enabled 1`인지, 서버/게임 포트가 같은지 확인한다. 콘솔의 `[Monitor]` 메시지를 확인한다.
- 포트 점유: 기존 수신 서버를 종료하거나 서버와 게임 양쪽 포트를 바꾼다.
- 게임 종료: 마지막 데이터는 유지되고 약 5초 후 수신 지연으로 표시된다.
- 브라우저를 보고 있는 동안 NPC가 멈춤: 게임의 기존 포커스 정지 규칙이다. 게임으로 돌아가면 재개한다.
- 실행 정책: 위 런처 명령의 Bypass는 해당 PowerShell 프로세스에만 적용된다. 영구 설정 변경 없이 Python 직접 실행도 가능하다.

마을 이동 확장 후 스키마 1에 `loaded`, `travelling`, `home_town`, `destination_town`, 경로 진행과 마을 인구·치안 필드를 추가했다. `npc.activity.10`은 마을 간 이동이다. 기존 예시 JSON은 필수 필드만 보여주는 호환 예시이며 실제 월드의 7개 마을 규모를 나타내지 않는다.
