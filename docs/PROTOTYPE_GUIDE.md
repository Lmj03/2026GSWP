# 프로토타입 02 — 계속 이어지는 도시와 한글 대화

사용자 작업 원칙에 따라 에이전트는 빌드·테스트·실행·화면 확인을 수행하지 않았다. 아래는 코드상 동작 의도이며 실제 화면 검증 보고가 아니다.

## 변경 내용

- 기존 잔광 지구의 수제 배치를 보존하고 바깥에 도로·건물·NPC를 자동 생성.
- 같은 좌표는 같은 배치로 생성되어 돌아와도 지형이 유지됨.
- 플레이어 중심 13×13 청크만 유지하고 먼 생성 데이터를 제거.
- 전역 청크 좌표는 64비트 정수, 이동·충돌·화면 좌표는 작은 상대 좌표로 분리.
- 미등록 구역의 경계선·이동 차단 제거, 플레이어를 따라가는 주변 지도.
- 게임 안내·목표·조작법·간판·NPC 이름과 대사를 한글로 변경.
- UTF-8 문구 파일, NPC별 대사 지정, 글자 폭 측정, 자동 줄바꿈과 긴 대사 페이지 지원.
- 목격 NPC의 기억은 청크를 떠났다가 돌아와도 실행 중에는 유지.

## 사용자 빌드·실행

Visual Studio에서 SimpleGame.sln을 열고 SimpleGame을 시작 프로젝트로 지정한 뒤 Debug / x64로 직접 빌드·실행한다. 기본 출력 위치는 x64/Debug/SimpleGame.exe다.

기존 v143 도구 모음, Windows SDK, OpenGL 3.3 기반이며 새 외부 패키지 설치는 필요하지 않다. Windows의 맑은 고딕을 요청해 글자 이미지를 메모리에 만든 뒤 OpenGL 텍스처로 표시한다. 시스템 글꼴 구성에 따라 대체 글꼴이 사용될 수 있으며, 한글 글꼴이 없는 환경까지 정확한 표시를 보장하지 않는다.

렌더러와 셰이더의 정점 형식이 함께 변경되었다. 예전 실행 파일이나 셰이더를 섞지 않는다. 빌드 후 작업에서 Shaders와 Data 전체를 출력 폴더에 복사하도록 설정했다. 특히 Data/Locale/ko.txt도 실행 파일 옆에 필요하다.

별도 배포 시 같은 아키텍처의 glew32.dll, freeglut.dll과 Shaders, Data 폴더를 EXE 옆에 둔다. 자원은 EXE 옆을 우선해서 읽으므로 소스 데이터를 수정한 뒤 다시 빌드해 복사하거나 출력 폴더의 데이터도 갱신해야 한다.

## 조작

| 입력 | 동작 |
|---|---|
| WASD | 화면 기준 이동 |
| Shift + WASD | 달리기 |
| E | 도움·대화, 여러 페이지 대화에서는 다음 페이지 / 닫기 |
| 휠 / + / - | 확대·축소 |
| M | 주변 지도 |
| R | 비 표시 전환 |
| Tab | 화면 안내 숨김·표시 |
| F2 | 시작 위치, 의료 키트, 인지도, NPC 기억 초기화 |
| Esc | 종료 |

도로를 따라 계속 이동하면 새로운 구역이 이어진다. 미니맵은 현재 주변 구역이며 세계 전체 지도가 아니다.

의료 키트는 시작 시 한 개다. 가까운 주민에게 E로 전달하면 인지도가 5가 된다. 여러 NPC가 가까우면 가장 가까운 대상이 선택되고 이름이 표시된다.

도움받은 주민과 반경 4.5타일의 목격자가 기억을 얻는다. 주민·정비사는 접근과 대사가 바뀌고, 목격한 조직원은 플레이어를 피한다. 벽에 가린 시야와 소문 전파는 아직 계산하지 않는다. 먼 NPC는 휴면 상태로 두고 가까워지면 갱신한다.

## 월드 생성과 기억

청크는 8×8타일이다. 플레이어가 청크 경계를 넘으면 기준점을 옮기고 주변 청크를 준비한다. 생성은 게임 스레드에서 수행하며 비동기 로딩은 아니다.

도로는 각 축에서 8로 나눈 나머지가 3 또는 4인 타일이다. 건물은 도로 밖 네 부지에 배치하고 일부 부지는 비워 둔다. 높이·간판·색상은 청크 좌표로 결정한다. 자동 생성 청크마다 NPC 한 명을 배치한다.

게임플레이용 맵 끝은 없지만 64비트 정수 표현의 물리적 한계는 있다. 방문한 지형 전체를 누적하지 않으므로 이동 거리만으로 청크 캐시가 계속 커지지 않게 구성했다. 장시간 성능은 사용자가 직접 확인할 대상이며 측정 결과는 없다.

NPC의 ID는 좌표로부터 안정적으로 만들어진다. 청크가 해제되어도 도움 기억을 가진 ID는 보관한다. 재방문 시 기억을 복원하지만 먼 NPC의 세부 이동 위치는 보관하지 않고 기본 위치에서 재개한다. 디스크 저장은 없어 종료나 F2로 기억과 인지도가 초기화된다.

## 수제 구역 추가

SimpleGame/Data/afterglow.district에 등록한 청크가 자동 생성보다 우선한다.

~~~text
chunk 3 0
building east_clinic 24.2 0.2 2.5 2.5 90 0 동쪽_진료소
npc east_doctor 1 27.5 4.4 동쪽_정비사
~~~

이 예시의 청크는 x=24~32, y=0~8이다. 등록한 청크에는 자동 건물·NPC를 생성하지 않으므로 원하는 배치를 직접 추가한다. 도로 규칙은 동일해서 인접 자동 구역과 연결된다.

| 행 | 형식 |
|---|---|
| 버전 | version 1 |
| 청크 | chunk cx cy |
| 시작점 | spawn x y |
| 건물 | building 고유ID x y 폭 깊이 높이 색상 간판 |
| NPC | npc 고유ID 역할 x y 이름 |
| 대사 연결 | dialogue NPC고유ID 기본문구키 기억후문구키 |

역할은 0 주민, 1 정비사, 2 조직원이다. 색상은 0 청록, 1 자홍, 2 주황이다. 이름·간판은 한글을 지원하며 공백은 밑줄로 입력한다. # 뒤는 주석이다. NPC와 건물의 ID는 서로 중복될 수 없다.

수제 파일의 청크 좌표 허용 범위는 현재 각 축 -256~256이다. 이 범위는 수제 배치 로더의 제약이며 자동 생성 월드의 이동 경계가 아니다. 건물 폭·깊이는 0 초과 8 이하, 높이는 20~400이다. 건물 전체 바닥 영역과 시작점·NPC는 등록된 수제 청크 위에 있어야 한다. 시작점·NPC가 건물에 겹치면 로딩 오류를 낸다.

## 한글 문구와 새 NPC 대사

SimpleGame/Data/Locale/ko.txt에 UTF-8로 문구를 추가한다. 한 줄에 키=내용이며 키는 중복될 수 없다. 내용에 =가 있어도 첫 기호만 구분자로 사용한다.

~~~text
dialogue.east_doctor.neutral={name}: 이 구역은 처음인가요? 정비소가 필요하면 저를 찾아오세요.
dialogue.east_doctor.remembered={name}: 주민을 도왔던 분이군요. 당신 덕분에 분위기가 달라졌어요.
~~~

맵 파일에서 NPC 선언 아래에 연결한다.

~~~text
dialogue east_doctor dialogue.east_doctor.neutral dialogue.east_doctor.remembered
~~~

{name}은 NPC 이름으로 바뀐다. 고유 대사를 지정하지 않은 NPC는 역할별 공통 한글 대사를 사용한다. 존재하지 않는 문구 키를 연결하면 로딩 오류로 안내한다.

대사는 실제 글자 폭으로 줄바꿈하고 72개 문자 단위로 페이지를 나눈다. 여러 페이지는 E로 넘기며 마지막 페이지에서 E로 닫는다. 한 페이지 문구는 일정 시간 후 숨겨진다. 현재는 일반 문장을 한 줄에 입력하며 별도 줄바꿈 이스케이프나 대화 선택지·음성 편집기는 지원하지 않는다.

첫 의료 키트 전달이 주민 대화보다 우선한다. 주민의 기본 대사는 키트를 사용한 뒤 기억이 없는 대상에게서 들을 수 있다.

## 사용자 확인 항목

- 기존 맵 끝과 음수 좌표 방향을 지나도 도시와 도로가 이어지는지.
- 청크 경계에서 화면·충돌이 갑자기 튀지 않는지.
- 먼 곳에 갔다 돌아와도 같은 배치와 NPC 기억이 유지되는지.
- HUD·간판·NPC 대사가 한글로 표시되고 대사창 안에서 줄바꿈되는지.
- 추가한 문구와 NPC별 대사가 나오며 긴 대사는 끝까지 넘겨 읽을 수 있는지.
- 줌·지도·창 크기 변경·HUD 숨김이 유지되는지.

## 남은 범위

전투, 정규 의뢰·장비 강화, 디스크 저장, 비동기 스트리밍, 정교한 길 찾기·소문 전파는 아직 없다. 자동 구역은 공통 도로 규칙과 제한된 건물 형태를 재조합하는 단계다. 네온·반사는 도형을 겹친 연출이며 물리 기반 조명·반사가 아니다.
